A clearer path through cross-database work.

For developers, DBAs and data engineers who work across more than one database. Each step below stands on its own; together they cover a cross-database job from start to finish: learn the schema, deal with dialect differences, then migrate with a plan.

Find your way around a database.

Connections, databases, schemas and objects share one tree. Open a table to read its DDL, then write SQL in a query tab beside it: the editor completes table and column names from the loaded schema, and large results arrive a page at a time.

  • Table and view DDL for 12 SQL engines, plus catalog browsing for MongoDB, Redis and Elasticsearch
  • A query's result is read page by page; paging and CSV export never run the SQL again
  • Destructive statements, such as a DELETE or an UPDATE without WHERE, ask for confirmation before they run

Understand what your SQL becomes.

Convert SQL between ten dialects, including PostgreSQL, MySQL, SQL Server, Snowflake, Oracle and DuckDB. A side-by-side diff shows which functions were rewritten and where the quoting changed; column lineage traces every output column back to its source table and column.

  • Conversion and analysis only parse your SQL: nothing is executed and no connection is needed
  • Constructs the target dialect cannot express, and lineage that cannot be resolved, are flagged explicitly

See the plan before the move.

Choose a source and a target, tick the tables to move, and dbfox runs a read-only preflight first. It maps every column type, flags tables that already exist on the target, and grades each mapping as L1 lossless, L2 lossy or L3 unmappable. Lossy and unmappable items wait for your explicit decision before any structure or data is moved.

  • Moves tables, primary keys, indexes, unique constraints and rows, then verifies row counts table by table
  • Views, foreign keys, triggers and other objects that are not migrated are listed in the plan; the plan and the result report export as JSON or Markdown

Give AI context. Keep control.

Connect an MCP-compatible assistant to dbfox and it can reuse your saved connections to read schemas, run read-only queries, convert SQL and draft migration plans. Writes and migration execution are not among its tools; they stay with you, in the workspace.

Your first three steps

  1. Add a connection

    Select New connection, pick the engine and fill in the details, or paste a connection string and let the form recognize its fields. Start with a read-only account.

  2. Open a table

    Expand the object tree and open a table to read its DDL, or choose Preview data (LIMIT 100) from its menu.

  3. Try it without a database

    SQL conversion in the top bar needs no connection: paste a statement, pick the dialects and select Convert.

Before you get started.

Do I need a dbfox cloud account?

No. dbfox runs on your machine and connects with your own database credentials. Connection profiles stay in a local data directory with their passwords encrypted; the key sits in the same directory, so protect it as you would the credentials. If you connect an external AI assistant, its own account and data-handling rules apply.

Can I run queries on every supported database?

SQL runs on twelve engines: PostgreSQL, MySQL, MariaDB, SQL Server, SQLite, Snowflake, DuckDB, DuckLake, Oracle, Db2, Redshift and ClickHouse. Elasticsearch accepts read-only SQL and search requests. MongoDB and Redis run native commands, including writes that the database account allows. Cancelling a query does not undo statements that have already committed.

Does migration guarantee an identical result?

No. Engines differ in types and semantics, and views, foreign keys, triggers and similar objects are outside the migration. Review the preflight mappings and warnings, try it on non-production data first, then check the result report. dbfox does not offer real-time CDC or zero-downtime migration.

Can an AI assistant write data through MCP?

No. The 15 MCP tools cover schema discovery, read-only queries, SQL analysis and migration planning; none of them writes to a database or runs a migration. Read-only queries are supported on PostgreSQL, MySQL, MariaDB, SQL Server and SQLite, and are not available for Snowflake or Elasticsearch. Use database permissions as well to limit what it can reach.

Is there a macOS or Linux version?

The desktop app is currently a Windows x64 installer only. On Linux, the Docker Compose bundle starts the same interface for use in a browser; its images are linux/amd64. There are no macOS or Linux desktop installers yet.
