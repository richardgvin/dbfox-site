01 / 从结构探索到迁移执行

跨数据库工作，从看清每一步开始。

为开发者、DBA 和数据工程师准备：先理解数据库，再处理方言差异，最后审阅迁移计划。

01

把结构放在手边。

从连接、数据库到对象，在同一棵结构树中逐级浏览。在 SQL 工作区旁查看 DDL，保留上下文。

  • 浏览四种数据库的表与视图 DDL
  • 在 PostgreSQL 和 MySQL 上执行查询
02

转换之后，差异一目了然。

在 PostgreSQL、MySQL、Redshift 与 ClickHouse 方言间转换 SQL，分析列血缘，并排审阅转换前后的结构变化。

  • 转换与分析不会执行 SQL
  • 明确呈现转换警告和未解析的血缘
03

先看清计划，再执行迁移。

选择来源与目标数据库、勾选表并运行预检。在迁移结构和数据前，审阅类型映射、目标冲突与处理策略。

  • 映射分级让转换风险可见
  • 查看执行报告与跳过的对象

04 / 在本地开始

你的数据库，你的工作台。

桌面应用在本地连接你的数据库。本网站用于产品介绍，不连接数据库，也不执行 SQL。

01

安装 Windows 桌面版

桌面应用使用 Windows MSI 安装包。安装后启动 dbfox，选择界面语言即可开始。

本站暂未提供公开安装包。完成版本与下载验证后，将在此提供下载入口。

02

添加数据库连接

选择数据库类型并填写连接信息。测试连接后打开数据库，从对象树查看结构。建议先使用只读账号。

03

单独配置 MCP

MCP 需要独立的 dbfox-mcp 可执行文件。如已获得源码仓库访问权限，可执行以下命令构建：

cargo build -p dbfox-mcp --release

在 MCP 客户端中将 stdio 命令指向构建后的可执行文件。安装桌面 MSI 不会自动配置 MCP；本站尚未提供独立程序下载。

05 / FAQ

开始之前，你可能想了解。

需要注册 dbfox 云账号吗？

本地工作台无需 dbfox 云账号，使用你自己的数据库凭据连接。若接入外部 AI 助手，其账号要求和数据处理规则由对应服务决定。

所有支持的数据库都能执行查询吗？

当前查询执行支持 PostgreSQL 和 MySQL。Redshift 与 ClickHouse 支持对象和 DDL 浏览、SQL 方言转换。取消查询不会撤销已经提交的语句。

迁移是否保证结果完全一致？

不同数据库在类型和语义上存在差异。请审阅预检映射与警告，先用非生产数据验证，再查看结果报告。dbfox 不承诺实时 CDC 或零停机迁移。

AI 助手可以通过 MCP 写数据吗？

当前 MCP 工具提供只读探索与迁移规划，不提供数据库写入或迁移执行。只读查询限 PostgreSQL 和 MySQL。请同时通过数据库权限限制访问范围。

有 macOS 和 Linux 安装包吗？

当前桌面打包流程面向 Windows MSI。本站未提供经过验证的 macOS 或 Linux 安装包。公开 Windows 安装包和独立 MCP 程序可用后会补充下载入口。
