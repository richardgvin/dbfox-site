跨数据库工作，从看清每一步开始。

写给同时面对几种数据库的开发者、DBA 和数据工程师。下面三步各自独立可用，连起来就是一次完整的跨库工作：先摸清结构，再处理方言差异，最后带着计划去迁移。

把结构放在手边。

连接、数据库、模式与对象排在同一棵树里。点开一张表就能读到它的 DDL；在旁边的查询标签里写 SQL，编辑器按已加载的结构补全表名和列名，大结果集一页一页读取。

  • 12 种 SQL 数据库的表与视图 DDL，以及 MongoDB、Redis、Elasticsearch 的目录浏览
  • 单条查询的结果逐页读取，翻页和导出 CSV 不会重新执行 SQL
  • DELETE、无 WHERE 的 UPDATE 等破坏性语句，执行前要求确认

转换之后，差异一目了然。

在 PostgreSQL、MySQL、SQL Server、Snowflake、Oracle、DuckDB 等 10 种方言之间转换 SQL。结果与原文并排对比，哪个函数被改写、哪里换了引号一眼可见；列血缘说明每个输出列来自哪张表的哪一列。

  • 转换与分析只解析 SQL，不会执行，也不需要数据库连接
  • 目标方言表达不了的写法、无法确定的血缘，都会明确标出

先看清计划，再执行迁移。

选好源库和目标库，勾选要迁移的表，dbfox 先做一次只读的预检：逐列给出类型映射，标出目标端已存在的表，并按 L1 无损、L2 有损、L3 不可映射三级标明风险。有损和不可映射的项目要等你明确决定如何处理，之后才迁移表结构与数据。

  • 迁移表、主键、索引、唯一约束与数据，并逐表校验行数
  • 视图、外键、触发器等未迁移的对象会列在计划里；计划和结果报告可导出为 JSON 或 Markdown

让助手理解结构，由你掌握执行。

把支持 MCP 的 AI 助手接到 dbfox，它就能沿用你已保存的连接去读结构、跑只读查询、转换 SQL、起草迁移计划。写入和迁移执行不在它的工具清单里，仍由你在工作台中完成。

装好之后的头三步

  1. 添加一个连接

    点“新建连接”，选择数据库类型并填写连接信息；也可以直接粘贴连接串，表单会自动识别各个字段。建议先用只读账号。

  2. 打开一张表

    展开对象树，点开一张表查看 DDL，或在它的菜单里选“预览数据（LIMIT 100）”。

  3. 没连库也能试

    顶栏的“SQL 转换”不需要数据库连接：贴一段 SQL，选好方言，点“转换”。

开始之前，你可能想了解。

需要注册 dbfox 云账号吗？

不需要。dbfox 在本机运行，用你自己的数据库凭据直接连接。连接配置保存在本机的数据目录，密码加密后存储；密钥也在该目录中，请像保护凭据一样保护它。若接入外部 AI 助手，其账号要求和数据处理规则由对应服务决定。

所有支持的数据库都能执行查询吗？

SQL 查询可在 12 种数据库上执行：PostgreSQL、MySQL、MariaDB、SQL Server、SQLite、Snowflake、DuckDB、DuckLake、Oracle、Db2、Redshift 和 ClickHouse。Elasticsearch 接受只读 SQL 与检索请求；MongoDB 和 Redis 执行原生命令，包括数据库账号允许的写入。取消查询不会撤销已经提交的语句。

迁移是否保证结果完全一致？

不保证。不同数据库的类型和语义存在差异，视图、外键、触发器等对象也不在迁移范围内。请先审阅预检给出的映射与警告，用非生产数据验证，再核对结果报告。dbfox 不提供实时 CDC 或零停机迁移。

AI 助手可以通过 MCP 写数据吗？

不能。15 个 MCP 工具只做结构探索、只读查询、SQL 分析和迁移规划，不提供数据库写入或迁移执行。只读查询支持 PostgreSQL、MySQL、MariaDB、SQL Server 和 SQLite，不支持 Snowflake 与 Elasticsearch。请同时用数据库权限限定它能访问的范围。

有 macOS 和 Linux 版本吗？

桌面应用目前只有 Windows x64 安装包。在 Linux 上可以用 Docker Compose 配置包启动同一套界面，在浏览器中使用；镜像为 linux/amd64。暂无 macOS 和 Linux 桌面安装包。
